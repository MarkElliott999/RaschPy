# Changelog

All notable changes to RaschPy are documented in this file.

## [1.3.0] - 2026-09-06

### Added
- **Wright maps (`wright_map`)** across all four model classes — `SLM`, `RSM`, `PCM`, and `MFRM` (with 8 model-specific aliases, `wright_map_global`/`_items`/`_thresholds`/`_matrix`/`_bivector`/`_centrality`/`_pseudo_halo`/`_bistretch`). Displays the distribution of person locations alongside item difficulties (and, for MFRM, facet-element/rater severities) on the same logit scale, either as back-to-back histograms/KDE curves or as a Winsteps-style item-name panel. `RSM`/`PCM`/`MFRM` additionally support a divided category-strip item display (`item_strip=True`) showing each item's own Rasch-Andrich threshold structure directly on the map, with disordered-threshold handling based on the most-probable-category envelope (not raw sorted threshold values). `MFRM` adds a facet-element panel (own dedicated panel or overlaid onto the items panel), and, for the three stretch models (`centrality`, `pseudo_halo`, `bistretch`), an additional stretch-factor (`omega`) panel bolted onto the figure (`show_stretch=True`). `expand_model=True` plots each rater's full reconstructed vector on the facet panel instead of a single point — the full (facet element, item, threshold) grid for `bivector`, or the per-threshold/per-item/per-(item, threshold) vector lambda and omega combine back out to for `centrality`/`pseudo_halo`/`bistretch` respectively (silently ignored for `global`/`items`/`thresholds`/`matrix`, which have no single-point/full-vector distinction to expand). Supports mean/±1SD/±2SD reference markers, person-group splitting (stacked/dodged/blended histograms or streamgraph/overlaid KDEs), vertical or horizontal orientation, and the usual theming/output options. Full worked examples added to every `Examples/Model classes/*` notebook and to the manual (one `wright_map` subsection per model class, in full).
- **Legend and explicit line labels for `crcs`/`threshold_ccs`** across all four model classes. The category/threshold curves now show a legend (`Category N` / `Threshold N`); `thresh_lines` gets a numeric label per threshold line, and `central_location` gets an explicit `"Central location: X"` text label — both previously unlabelled.
- **Multi-item overlay for `icc`/`iic`** across all four model classes — `item` (and, for `MFRM`, `facet_element`) now also accepts a list, overlaying several curves on one plot with automatic per-curve colouring, a legend, and collision-avoided (pixel-measured, not guessed) label placement for `central_location`/`score_lines`/`point_info_lines`. Single-item calls are unchanged. Manual updated (`item` row, `icc`/`iic` sections, per model class).
- **New default palette, `'colorblind multi'`** (Okabe & Ito, 2008), across all four model classes. Replaces `'dark blue'` (a single-hue gradient, low-contrast between curves) as the default for every curve plot, and `'dark multi'` (not colour-vision-deficiency-safe) as the default for `wright_map`'s item-strip categories. Both old palettes remain available by name. Manual updated (`palette` row, Shared plotting arguments section, per model class, including `wright_map`'s item-strip default).
- **`marker_border` argument** on `icc`/`crcs`/`threshold_ccs`/`tcc`, across all four model classes. Defaults to `True`, giving observed-data (`obs=`) markers a black edge, matching `plot_anchor_selection`'s own marker style; pass `marker_border=False` for a plain, edge-free marker. Manual updated (Shared plotting arguments section, per model class).
- **10 new `plot_style` schemes** — `'black'`, `'parchment'`, `'minimal'`, `'print'`, `'solarized-light'`, `'solarized-dark'`, `'slate'`, `'blueprint'`, `'newsprint'`, and `'chalkboard'` — alongside the original `'white'`/`'dark'`, on every plotting method across all four model classes. Implemented as one shared `Rasch._apply_plot_style()`/`_PLOT_STYLE_RC` mapping in `base.py` rather than duplicated per file, so a new scheme only needs to be added once. Also fixed a latent bug this surfaced: `wright_map`'s (and `std_residuals_hist`'s) own style-setup code called `plt.style.use('seaborn-v0_8-' + plot_style)`, which would have raised for any of these new names (no such built-in stylesheet exists) — removed in favour of the same shared rcParam-based approach `plot_data` already used, which needs no matching built-in stylesheet. Manual updated (`plot_style` row, Shared plotting arguments and `wright_map` sections, per model class).
- **`line_border` argument**, alongside the new schemes — draws each curve line with a thin contrasting stroke (white on the five darkest schemes, black otherwise), so it stays legible against a background or gridline colour close to its own. Off by default (`line_border=False`), on `icc`/`crcs`/`threshold_ccs`/`tcc` across all four model classes. Manual updated (Shared plotting arguments section, per model class).
- **`'colorblind multi'`'s black entry is swapped for white** on the five darkest `plot_style` schemes (`'black'`, `'solarized-dark'`, `'slate'`, `'blueprint'`, `'chalkboard'`), where it would otherwise render invisibly. The other 7 Okabe–Ito hues are unchanged on every scheme.
- **`check_data_connectivity()` also checks *strong* connectivity** of the directed win-graph, reported as a new `strongly_connected` key. When the graph is connected but not strongly connected (near-Guttman data, very short tests), a `UserWarning` names the components and notes that `calibrate(method='log-lik')` on its default unpowered matrix has no finite solution there (Ford, 1957) — use `method='cos'`/`'ls'`/`'evm'`, `matrix_power>=1`, or a larger `constant`. Runs once at construction; no cost to `calibrate()` or bootstraps. Manual updated (per model class).
- **`SLM.calibrate(robust=...)` and `constant=None`.** `constant` now defaults to `None`, which resolves to `0.1` — no change in behaviour. Passing `robust=True` (with `constant` left `None`) instead sets the additive smoothing constant to `min(1.0, sqrt(0.004 * m))`, where `m` is the mean number of persons responding to both items, averaged over all item pairs. The rule was fitted over a large simulation (8400 design cells x 23 constants x 80 replications) to minimise the worst-case (95th-percentile) RMSE of item-location recovery: it applies negligible smoothing to sparse designs, more as the paired-observation count grows, and levels off at `1.0` (beyond which the constant has no material effect on the estimates). An explicit `constant=` always takes precedence over `robust`; passing both raises a `UserWarning` and uses the explicit value. The resolved constant is stored as `self.constant`. Default output (`constant=None`, `robust=False`) is identical to before. `robust=` / `constant=None` are now also threaded through every `SLM` method that recalibrates (`calibrate_anchor`, `std_errors`, `fit_statistics`, `dif_test`, `res_corr_analysis`, `item_stats_df` / `person_stats_df` / `test_stats_df`, `save_stats`, `save_residuals`), each defaulting to `robust=False` so their output is unchanged. Manual updated (`SLM` `calibrate` section).
- **`RSM.calibrate()` — `constant=None` two-stage default, plus a new `threshold_constant`.** `constant` now defaults to `None`, resolving to `0.1` for the Stage 1 (PAIR) item pairwise matrix. The Stage 2 (CPAT) threshold stage takes a **separate** default of **`0.03`**. The threshold stage needs less additive smoothing because CPAT already regularises through its harmonic-mean information weighting — thin pairwise-comparison cells contribute little regardless of the additive term (weighted CPAT recovers thresholds consistently better than unweighted, Elliott & Buttery 2022) — so the constant only has to keep the log-ratios finite. A scalar sweep (`constant_study_RSM_scalar_sweep.ipynb`; ~1600 designs across well-conditioned, edge — tight scales / small N / missing data — and disordered-threshold regimes, 120 replications each) puts the threshold-recovery RMSE and slope-bias optimum at or below `0.03` (mean, median and 95th-percentile alike) in the edge and disordered regimes; well-conditioned data's RMSE optimum is nearer `0.08`–`0.10` but the curve is flat enough there that `0.03` costs only a few thousandths of a logit in typical RMSE while tightening the recovery-slope distribution's upper tail, so a single `0.03` is used throughout. Versus `0.1`, `0.03` gives ~6% lower mean threshold RMSE and ~20% lower mean `|beta - 1|` overall (up to ~10% RMSE in tight scales). The new **`threshold_constant`** argument sets the Stage 2 constant independently: `None` (default) follows `constant` — `0.03` when `constant` is `None`, else the explicit `constant` value; a float overrides. So `constant=0.1` reproduces the pre-1.3.0 output exactly (`0.1` for both stages), `constant=None` gives the tuned `0.1`/`0.03` split, and `threshold_constant=t` changes only the threshold stage. `self.constant` and `self.threshold_constant` record the resolved values. `constant` / `threshold_constant` are threaded through every `RSM` method that recalibrates (`calibrate_anchor`, `std_errors`, `fit_statistics`, `dif_test`, `model_selection`, `res_corr_analysis`, `item_stats_df` / `threshold_stats_df` / `category_stats_df` / `person_stats_df` / `test_stats_df`, `save_stats`, `save_residuals`); `model_selection`'s internal `PCM` fit takes the single item-stage constant. (`RSM` uses no data-adaptive `robust` rule — unlike `SLM`, the RSM pairwise counts do not develop the near-empty cells that such a rule guards against; see **Changed** for the output shift.) Manual updated (`RSM` `calibrate` section).
- **`PCM.calibrate()` — `constant=None` default and a `robust=` two-pass rule.** `constant` now defaults to `None`, resolving to `0.1` (the pre-1.3.0 value; explicit `constant=0.1` is unchanged). Passing `robust=True` (with `constant` left `None`) instead uses a two-pass smoothing construction, solved throughout with `method='cos'`: pass 1 at a scalar `c₁ = 2.5·φ`, `φ = clip(0.0865·K⁻¹·⁷²·c̄·e^{1.27m}, 0.02, 60)` (`K` = maximum score, `c̄` = mean off-diagonal count of `C + Cᵀ`, `m` = missing-data proportion); pass 2 re-solves with a per-pair constant `c_ab = max(c₁(1 + h·|d̂_a − d̂_b|), 0.02)`, `h = −max(0.6/K, 0.1)`, tapered by the pass-1 threshold-estimate gap. It is a targeted guard for heavy missing data (≳ 60%) combined with a long rating scale (`K` ≳ 5), where per-pair counts become too thin for a flat constant; a flat `constant=0.1` matches or beats it elsewhere. An explicit `constant` takes precedence over `robust` (with a `UserWarning`); `self.constant` records the resolved value (the pass-1 scalar under `robust=True`). `constant` / `robust` are threaded through every `PCM` method that recalibrates (`calibrate_anchor`, `std_errors`, `fit_statistics`, `andersen_lr_test`, `dif_test`, `model_selection`, `res_corr_analysis`, `item_stats_df` / `threshold_stats_df` / `category_stats_df` / `person_stats_df` / `test_stats_df`, `save_stats`, `save_residuals`), each defaulting to `robust=False` so their output is unchanged; `model_selection`'s internal `RSM` fit is left at its own defaults. Default additive smoothing constants were determined through simulation studies. Manual updated (`PCM` `calibrate` section).
- **`MFRM.calibrate()` — per-stage tuned constants, per-model `method` selection, `threshold_constant`, and `robust=`.** `constant` now defaults to `None`, resolving to simulation-tuned values per stage: item-location (`item_diffs`) `0.1`, threshold-location (`ra_thresholds`) `0.3`, and the facet-element (rater) stage a per-model value — `0.1` for `global`/`centrality`/`pseudo_halo`/`bistretch`, `0.3` for `items`/`thresholds`/`bivector` (matrix-marginal route), and for `matrix` the data-adaptive `clip((0.68 − 0.22·m)/√R, 0.15, 0.5)`, with `m` the observed proportion of missing responses and `R` the number of facet elements. `method` now defaults to `None`, resolving by estimand density: `'log-lik'` for the low-parameter representations — `global` (one severity per facet element, from a small dense facet-element × facet-element matrix) and the three stretch models `centrality`/`pseudo_halo`/`bistretch` (whose parent vector is re-pooled through a robust slope regression) — and `'cos'` for `items`/`thresholds`/`matrix`/`bivector`, where the estimand is a thin per-item/per-threshold/per-cell/per-marginal slice with no downstream re-pooling and `'cos'` degrades more gracefully on the sparser comparison sub-matrices (this partly reverses the package-wide `'cos'`→`'log-lik'` default flip below, for `MFRM`'s four sliced representations only). New **`threshold_constant`** sets the `ra_thresholds` stage independently, mirroring `RSM`: `None` follows `constant` (`0.3` when `constant` is `None`, else the explicit value). New **`robust=`** selects the more conservative / tail-protective calibration for rough data, resolved per model — `matrix`: the rater-cell constant switches to the R-only `clip(0.65/√R, 0.15, 0.5)` (drops the missing-data term); `bivector`: switches to the direct pooled-PAIR marginal estimator with a larger rater-stage constant (~`2.0`); `bistretch`: the rater/stretch-stage constant drops from `0.1` to `0.05`. For every other model `robust=True` currently has no effect and is accepted only for forward compatibility (a future rule can then be added without an API change). `matrix_marginals` default is now `None`, resolving to `not robust` for `bivector` (matrix-marginal means unless `robust`) and `True` for `bistretch` (always — direct marginals bias its stretch parameters toward `omega = 1`). An explicit `constant=` overrides every stage and takes precedence over `robust` / `threshold_constant` (`UserWarning` if `robust` is also passed). `self.constant`, `self.threshold_constant`, and `self.facet_constant` record the resolved values. `constant=0.1` (with `method='cos'`, `matrix_power=3`) reproduces pre-1.3.0 output. `constant` / `threshold_constant` / `method` / `robust` are threaded through every `MFRM` method that recalibrates. Default additive smoothing constants were determined through simulation studies. Manual updated (`MFRM` `calibrate` section).

### Fixed
- **`PCM._build_pairwise_matrix()` counted same-item threshold cells.** The joint score-category frequency matrix is built over one-hot category blocks concatenated across all items, and cells linking two thresholds of the *same* item were left populated by that construction — a person has one score per item, so such a cell is a category-frequency count relabelled as a pairwise comparison, not a genuine one (and for non-adjacent thresholds of the same item it is a structural zero regardless of sample size). This biased both item-location and threshold recovery slightly outward (recovery slope > 1, concentrated at the extreme thresholds; roughly 13–16% at `constant=0` in simulation, largely independent of sample size). Same-item cells are now forced to zero after the matrix multiplication. Present since v1.0.0. Changes bare `PCM.calibrate()` output and everything downstream; `PCM` regression fixtures and `Examples/Model classes/PCM` outputs regenerated. `constant`-tuned defaults (above) were chosen against the corrected matrix.
- **`MFRM_Sim_Bivector` (and `MFRM_Sim(model='bivector')`) now generates the identified representation.** The `threshold_effects` table was centred only per threshold (across facet elements), leaving a non-zero mean within each facet element's own row — a per-facet-element level the bivector estimator structurally assigns to the *item*-effect axis instead (the `full[r,i,k] = item_effect[r,i] + threshold_effect[r,k]` split has a per-facet-element gauge freedom, which the estimator pins by forcing `threshold_effect` to sum to zero within each facet element). A direct table-for-table comparison of recovered vs. generating `threshold_effects` therefore showed a spurious ~20% compression (recovery slope ≈ 0.8) that vanished once the vectors were re-centred per facet element. The simulator now applies that second centring itself — subtracting each facet element's mean from its `threshold_effects` row and folding it into the corresponding `item_effects` row — so `full` (and hence every sampled response) is unchanged but recovered and generating parameters are now directly comparable. Recovery of the threshold marginal measures ≈ 0.98 as expected. `MFRM_Sim_Bistretch` is unaffected (its implied `threshold_effects` were already zero-sum per facet element). Present since v1.0.0. Bivector regression fixtures and the bivector example notebook's recovery cells updated.
- **`std_residuals_plot(black=True)` now works on `RSM`/`PCM`/`MFRM`** — the underlying shared histogram renderer already supported black-and-white mode, but only `SLM`'s own `std_residuals_plot` exposed the `black` argument; the other three silently dropped it.
- **Observed-data markers could render behind their curve line**, hiding `marker_border`'s edge entirely where a marker sits on (or very near) its own modelled curve — Matplotlib's default z-order draws `Line2D` curves above `PathCollection`/`Line2D` markers regardless of draw order. Fixed with an explicit `zorder` on every observed-marker call across all four model classes, and on `plot_anchor_selection`'s own markers.
- **`crcs`/`threshold_ccs` observed-data markers could be coloured to the wrong curve** when `obs=` selected a non-contiguous or reordered subset of categories/thresholds (e.g. `obs=[1, 3]`) — the marker colour was chosen by the observed series' position within the requested subset, not by which curve it actually belongs to, so it silently borrowed a neighbouring curve's colour instead of matching its own. Fixed across all four model classes; `icc`/`iic`'s own multi-curve `obs` (always in curve order already) is unaffected.
- **`priority_vector(method='log-lik')` diagonal contamination** — the Bradley–Terry MM update counted the non-zero diagonal of the matrix-power-resolved matrix in its win totals but not in the denominator. The `i`-vs-`i` cell is now excluded from both. Changes `'log-lik'` estimates (typically <0.2 logits); `'cos'`/`'ls'`/`'evm'` unaffected. Present since v1.0.0. (`'log-lik'` is now the default — see Changed.)
- **`wright_map`'s divided category strip left an unexplained gap at the open (unbounded) top/bottom categories** on `RSM`/`PCM`/`MFRM` — those categories only drew out to a width borrowed from the adjacent bounded segment (or a small fallback buffer), leaving blank panel background between the end of the strip and the axis edge. They now always draw flush to the location axis limits, in a flat block of the category's own colour by default. `neutral_extremes=True` still applies its fade-from-neutral-cream treatment, but that argument now controls only the fade — not whether the extreme reaches the edge, which it always does. Docstrings and manual updated (`neutral_extremes` row, per model class).
- **`wright_map(distribution_markers=True)` could clip the outermost μ±2σ tick and its label** on all four model classes. The location-axis range was taken from `floor`/`ceil` of the raw person/item (and, for `MFRM`, facet) data extent only; when a distribution is wide or heavy-tailed relative to its sample size, `mean ± 2·SD` can fall outside that extent, so the `μ+2σ`/`μ−2σ` mark was drawn (`clip_on=False`) just past the spine and cut off at the figure edge. The range now also spans every drawn distribution's `mean ± 2·SD` (per person-group when `group_by` is set) before the `floor`/`ceil`, so the marks always stay on-canvas. Only affects `distribution_markers=True` maps where a mark previously fell outside the data extent; the histogram/KDE binning shifts with the widened range in those cases. `Examples/Model classes/*` wright-map images regenerated.

### Changed
- **Default priority-vector method changed from `'cos'` to `'log-lik'`**, and its `matrix_power` default from `3` to `None` (resolving to `0` — no powering — for `'log-lik'`, and to `5` for every other method — raised from the previous fixed `3` after a power sweep found `SLM`/`RSM`/`MFRM` plateau by `2`–`3` while `PCM`'s wider item-threshold graph keeps improving to `5`–`6`; a no-op for `'log-lik'` and for the three plateaued models), on every `calibrate*` / `std_errors` / `model_selection` across all four model classes and on `base.priority_vector()`. `'log-lik'` is the Bradley–Terry maximum-likelihood fixed point — a lightweight iteration on the pairwise matrix, not a data-scale procedure like JML/MML — and handles an incomplete comparison graph natively, so it needs no matrix powering (whose transitive path counts in fact measurably worsen its recovery). A simulation study (SLM; full and 55%-sparse; small and large person/item samples) gave it the **lowest item-recovery RMSE of the four methods in every cell** — trivial on dense data, up to ~10% under sparsity — at ~1–2× the wall time of `'cos'` (a few ms). **This changes numeric output wherever `method=`/`matrix_power=` are not passed explicitly**, plus everything downstream (`item_stats`, SEs, DIF, `model_selection`, bootstraps) and the regenerated `Examples/Model classes/*` outputs. Pass `method='cos'` (with `matrix_power=3` if wanted) for the previous behaviour; `'cos'`/`'ls'`/`'evm'` output is bit-identical to before when selected explicitly. `'log-lik'` needs a strongly connected comparison graph (`check_data_connectivity` warns otherwise). Manual updated throughout.
- **Performance: `base.priority_vector()`.** `'log-lik'` warm-starts its MM iteration from the (inverted) cosine solution, roughly halving the iteration count — tens of passes over the item×item matrix on the default unpowered path (fewer as the item set grows and the comparison graph densifies), ~1 on a powered matrix — and gains a `max_iter` guard with a non-convergence warning. `'evm'` caps the PCA at its one used component (`n_components=1`); `'cos'` sheds redundant allocations; the PCM threshold-label list is cached across calls. `'cos'`/`'ls'` bit-identical to before, `'evm'` unchanged bar floating-point. `'cos'` is now documented (code and manual) as the Kou & Lin (2014) cosine maximisation method.
- **`RSM.calibrate()` default output changes** because the Stage 2 threshold constant now defaults to `0.03` rather than `0.1` (see Added). Stage 1 item locations are unchanged (still `0.1`); the Rasch–Andrich thresholds shift — typically <1% RMSE on well-conditioned data, more in tight rating scales — and with them `threshold_se`, `cat_width_se`, `person`/`test` statistics, threshold DIF and bootstraps. Pass `constant=0.1` (or `threshold_constant=0.1`) for the pre-1.3.0 behaviour — bit-identical to the old `RSM.calibrate()`. `SLM` output is unchanged. `RSM` regression fixtures regenerated; `Examples/Model classes/RSM*` outputs still to regenerate.
- **`PCM.calibrate()` default output changes** because `_build_pairwise_matrix()` no longer counts same-item threshold cells (see Fixed). Bare `PCM.calibrate()` item locations and thresholds shift — the recovery slope, previously biased outward to ~1.13–1.16, comes back to ~1.0 — and with them `std_errors`, `fit_statistics`, DIF, `model_selection` and bootstraps. Pass `constant` unchanged; there is no flag to restore the old matrix (the previous behaviour was a bug). `PCM` regression fixtures and `Examples/Model classes/PCM` outputs regenerated.
- **`MFRM.calibrate()` default output changes** (see Added). With arguments left at their defaults the calibration now uses `'cos'` for `items`/`thresholds`/`matrix`/`bivector` and `'log-lik'` for `global` and the stretch models, plus the tuned per-stage / per-model constants, rather than a uniform `'log-lik'` + `0.1`. Simulated parameter recovery against the previous `'cos'` + `0.1` behaviour: item locations essentially unchanged; threshold locations ~2–15% lower RMSE (largest for `matrix`/`bivector`/`items`, where the threshold-stage constant rises `0.1`→`0.3`); rater-facet vectors within a few percent on RMSE, with the `matrix` rater cells and `bivector` marginals improving most — `matrix` rater-cell recovery slope `1.02`→`0.99`, `bivector` rater item-marginal `1.04`→`0.99` (both onto `1`), `bivector` rater threshold-marginal RMSE down ~13% at slope ≈`0.98`; person locations within ~1% throughout. All `MFRM` regression fixtures and `Examples/Model classes/*MFRM*` / stretch-model outputs regenerated. Pass `constant=0.1`, `method='cos'`, `matrix_power=3` for the pre-1.3.0 result.
- **`category_base` default changed from `1` to `2` in `PCM_Sim`, `RSM_Sim` and `MFRM_Sim`** (and, through `**kwargs`, every `MFRM_Sim_*` subclass). Category widths are drawn `uniform(max_disorder, 2·category_base − max_disorder)`; at `category_base=1` (i.e. `uniform(0, 2)` with the default `max_disorder=0`) the width density is non-zero right down to `0`, so a `max_score=5` instrument drew a category narrower than `0.2` logits in roughly 40% of simulations and narrower than `0.1` in roughly 20% — a near-collapsed category whose implied threshold structure no set of ordered dichotomous item characteristic curves reproduces (a soft disordering). `category_base=2` roughly doubles the expected minimum category width and halves those near-degenerate rates without changing the shape of the draw. This changes the generated data — and therefore every recovered parameter — for any `PCM`/`RSM`/`MFRM` simulation that does not pass `category_base=` explicitly. `SLM_Sim` is dichotomous and unaffected. `PCM`/`RSM`/`MFRM` regression fixtures and the `Examples/Model classes/*` / `Examples/Simulations/*` outputs regenerated. Pass `category_base=1` for the pre-1.3.0 generating distribution. Manual updated (`MFRM_Sim`, `PCM_Sim`, `RSM_Sim` and stretch-model simulation sections).

## [1.2.2] - 2026-08-23

### Fixed
- **`MFRM` matrix-marginal bivector option bug fix** `_estimate_raters_matrix()`'s `marginal_facet_effects_thresholds` (used by `calibrate(model='bivector', matrix_marginals=True)` and `'bistretch'`) omitted per-facet-element recentring as anchoring (`_calibrate_anchor_matrix`) already applied — threshold estimates carried the mean item effect. Present since v1.0.0. Fixed by applying the same recentring in the plain (non-anchor) path. Previous default behaviour (False) was working correctly. Since performance with corrected `matrix_marginals=True` now outperforms direct estimation, as per Elliott & Buttery (2022a), default flipped to `matrix_marginals=True` (see below).

### Changed
- **`calibrate()`'s `matrix_marginals` default flipped from `False` to `True`** for `bivector`/`bistretch`, matching the `_estimate_raters_bivector()` default and the findings of Elliott & Buttery (2022a) that taking matrix marginal means outperforms direct bivector estimation in almost all conditions. Confirmed by simulation (RMSE 0.39 vs 0.43 for threshold recovery under a true `'thresholds'`-model rater). This changes numeric output when `calibrate(model='bivector')`/`'bistretch'` is called without passing `matrix_marginals=` explicitly. Also impacts `model_selection()`, `std_errors()`, and bootstrapping, none of which passed `matrix_marginals=` explicitly.

## [1.2.1] - 2026-08-19

### Changed
- **Performance: vectorized PAIR/CPAT pairwise-matrix construction** across RSM, PCM, and MFRM. All routines vectorised as far as possible, replaced (often nested) raw Python for-loops with matrix multiplication, following the approach already in place for SLM. Applies to PAIR estimation for items and raters in `_build_pairwise_matrix()` (RSM/PCM/MFRM item calibration) and `_estimate_raters_global()`/`_pair_matrix()` (MFRM rater estimation), and also to CPAT threshold estimation `_threshold_distance()`. Also eliminated redundant dataframe build calls. No API or behaviour change — verified numerically identical to the prior implementation. Performance improvement on small-scale testing showed speeding up of ~1.2x (global, larger designs) to ~2.6x (bivector); benefits `std_errors()` bootstrap loops most, since this involves repeated calibration calls, so may be second or even minutes rather than milliseconds there.

## [1.2.0] - 2026-08-06

### Added
- **Three new MFRM rater-severity parameterisations**, each a closed-form restriction of an existing fully-free representation — no new estimation machinery, derived directly from an already-calibrated fit:
  - `model="centrality"` (alias `"threshold_stretch"`) — Jin & Wang (2018)-style rater centrality/extremity: a shift `beta_r` plus a stretch `alpha_r` applied to the reference thresholds, restricting the `"thresholds"` parameterisation. Sits strictly between `"global"` (1 free param/rater) and `"thresholds"` (K free params/rater) on the model-selection ladder.
  - `model="pseudo_halo"` (alias `"item_stretch"`) — the item-facet analogue: a shift `beta_r` plus a stretch `gamma_r` applied to reference item locations, restricting `"items"`. Named `pseudo_halo` deliberately — it tests compressed item-difficulty *perception* under an otherwise locally-independent response process, not classic halo effect's usual mechanism (elevated local item interdependence); pair with `item_res_corr_analysis`/`facet_res_corr_analysis` run per-rater to check for that separately.
  - `model="bistretch"` — combines both stretch axes at once: a shift `beta_r`, an item-difficulty-stretch `gamma_r`, and a threshold-stretch `alpha_r`, restricting `"bivector"`. Sits strictly between `"global"` and `"bivector"` on the model-selection ladder — the parsimonious middle ground when a rater shows genuine structure on both axes simultaneously.
  - All three integrate at full parity with the original five representations: `calibrate()`/`calibrate_anchor()`, `fit_statistics()`, `std_errors()` (bootstrap SEs), every `*_stats_df()` table, `model_selection()` (AIC/BIC/LR, with LR degrees of freedom against both the parent model and `"global"`), and all plotting methods (`icc`, `crcs`, `threshold_ccs`, `tcc`, `test_info`, `test_csem`, `std_residuals_plot`, etc.) — the MFRM rater-parameterisation family is now eight representations, not five.
  - Matching simulation classes `MFRM_Sim_Centrality`, `MFRM_Sim_PseudoHalo`, `MFRM_Sim_Bistretch` for genuine parameter recovery testing.
- **`item_stretch`/`threshold_stretch` aliases** for `pseudo_halo`/`centrality` — axis-based names matching the `"items"`/`"thresholds"` and `"bistretch"` naming convention. Work everywhere a model name is accepted: as the `model=`/`models=` value, and as the method-name suffix (e.g. `calibrate_threshold_stretch()`) for every method family with a `_centrality`/`_pseudo_halo` variant. Resulting attributes are still stored under the canonical `_centrality`/`_pseudo_halo` names regardless of which spelling was used.
- **`model_selection(models=...)`** — restrict the eight-way comparison to a chosen subset (e.g. a direct two-model test) without paying the cost of calibrating the rest.
- **`per_rater_model_selection()` extended to all eight representations, plus a new `models=` parameter.** Under `test='LR'`, the existing top-down ladder (`matrix → bivector → {items, thresholds} → global`) now runs one additional targeted stretch test depending on which of those five wins, so any rater can be assigned any of the eight representations rather than just the original five. `test='AIC'`/`'BIC'` (AIC is the default) instead pick the minimum-criterion model directly across all active representations, with no ladder involved. `models=` restricts which representations are eligible — for `test='LR'`, `{'global', 'items', 'thresholds', 'bivector'}` must stay included as the mandatory backbone the ladder's fork needs, while `'matrix'` and each stretch model are independently toggleable; for `test='AIC'`/`'BIC'` it is a direct filter over any non-empty subset.

### Fixed
- **MFRM row-order canonicalisation** (the fix v1.1.1's own changelog described) had been silently reverted by the refactor commit that produced that release, and shipped broken in v1.1.1 — any `MFRM` where facet_elements (raters) rate non-overlapping person sets could crash (`IndexError`) or silently corrupt facet/rater severity estimates via a mis-shaped positional reshape. Restored and reverified: `check_data_connectivity()` and `calibrate()` both now behave correctly on ragged rater×person designs.
- `MFRM_Sim_Centrality`/`MFRM_Sim_PseudoHalo`/`MFRM_Sim_Bistretch` raised `TypeError: got multiple values for keyword argument 'manual_items'` if a caller passed `manual_items=`/`manual_thresholds=`/`manual_persons=`/etc. directly to the constructor — fixed.

## [1.1.1] - 2026-07-23

### Added
- **Differential Item Functioning (DIF) testing**: `dif_test()` on `SLM`, `PCM`, and `RSM` — tests every item for DIF against a person-level covariate (`self.exogenous`), with anchor purification (robust-z or Wald-based outlier trimming) before testing, per-item Wald and/or likelihood-ratio tests, an omnibus joint test, BH/Bonferroni multiple-comparison correction, and optional ETS-style A/B/C severity categories (Zwick, Thayer & Mazzeo, 1997). `PCM`/`RSM` additionally report differential category functioning (DCF) via `threshold_dif_table` — tested via category *widths* rather than raw threshold locations, since a single genuine width change otherwise cascades into every downstream threshold.
- `calibrate_anchor()` added to `SLM`/`PCM`/`RSM` for item-bank anchoring (equating a new form's items onto a bank's known difficulties), sharing the same robust anchor-selection machinery as DIF purification.
- `andersen_lr_test(split_by='exogenous', covariate=...)` on `SLM`/`PCM`/`RSM` — Andersen's (1973) likelihood-ratio invariance test generalised to split by any exogenous person covariate, not just a median split on ability/score. (Not available on `MFRM`, where `andersen_lr_test` remains disabled for an unrelated reason — see Fixed/known issues.)
- `welch=True` option on `dif_test()` (all three models) for Welch–Satterthwaite t-tests instead of z-tests when group sizes are small or unequal; `size_adjust=True` for Tristán (2006) sample-size-adjusted standard errors.
- New worked example: `Examples/DIF testing/DIF testing example.ipynb`.

### Fixed
- Andersen/omnibus DIF tests were over-rejecting under the null (~1.3–1.7x nominal Type I error) because the alternative-hypothesis log-likelihoods used each subgroup's own separately-estimated person locations instead of the pooled model's — fixed across `SLM`/`PCM`/`RSM`.
- `PCM`'s omnibus DIF test additionally under-charged its degrees of freedom for per-item threshold/step-structure freedom, causing much larger false-positive inflation (~60% rejection under the null); fixed via a properly-scoped `omnibus_scope='item'|'full'` option.
- `MFRM.__init__` now canonicalises person row order on construction — a positional-reshape bug could otherwise silently collapse rater severity estimates toward zero when an `MFRM` was built from a non-canonically-ordered person subset.

### Changed
- `category_counts_df` (SLM, PCM, RSM, MFRM) rewritten to take `persons=`, `items=` (and, for MFRM, `facet_elements=`) filters plus a `counts_name=` option to store multiple named results side by side, instead of always computing across the full dataset. `category_counts_item` is folded into this method and removed as a separate call.
- Internal naming conventions standardised across `base.py`, `slm.py`, `pcm.py`, `rsm.py`, `mfrm.py`, `loaders.py` — `ability`/`abilities`/`difficulty`/`difficulties` renamed to `person_location(s)`/`item_location(s)` (and related parameter names) for consistency, fixing several naming-related bugs along the way.
- Package `__init__.py` consolidated under `raschpy/` (previously partly under a stray top-level `RaschPy/`), with an explicit documented `__all__` public API surface.

### Documentation
